# Watching the equations along a squat

The inspector can show the parts of paper equations 2a–2c alongside the motion.
Use an existing squat generated by this repository, with its task metadata:

```bash
python -m o2s.tracking.inspect data/refs/learning/shallow.npz \
  --controller stabilized-ff --equations --view --out runs/equations_ff_01
python -m o2s.tracking.inspect data/refs/learning/shallow.npz \
  --controller stabilized-pd --equations --view --out runs/equations_pd_01
```

Use a new output directory. On macOS, use `mjpython` for the viewer. Omit `--view`
for a fast headless run; `--equations` still prints values every 0.2 simulated
seconds and at episode end. This mode requires the optimizer dependencies
(Crocoddyl and Pinocchio) to reconstruct costs. It adds measurement work, so the
viewer targets real time but can run slower on a slower computer.

The original six-panel `diagnostics.png` is retained. Additional files are:

| File | What to inspect |
|---|---|
| `equations.png` | Ten panels grouped by equation: costs, force-balance terms, contact velocities/accelerations, CoM and sole motion |
| `equations.npz` | Every physics substep's equation vectors, plus planned running/terminal costs and CoM target |
| `equations.json` | Units/conventions, objective provenance, solver settings and maximum balance residuals |

## Equation 2a: what the optimizer prefers

The top-left plot shows **planned** objective contributions at each reference
interval: CoM tracking, posture/velocity regularization, torque regularization,
joint-limit barriers and each foot's wrench barrier. Running contributions include
20 ms integration and Crocoddyl's quadratic factor of 1/2. The top-right plot
separately shows terminal contributions. Axes use symmetric-log scaling so a large
term does not hide small terms or zeros. These are weighted costs, not physical
units or the tracking environment's rewards.

The CoM panel shows three distinct quantities: the requested task profile,
the optimized trajectory, and the simulated trajectory. The planned objective
plots cover the **whole reference**, even if the simulation falls early. They
are the same for PD and FF runs of the same reference; their simulation curves
can differ. The terminal bar is a planned value, not an assertion that a fallen
robot reached that state.

Costs are re-evaluated with the optimizer's existing cost models, without solving
again. New references record their `SquatWeights`. Legacy references use the
current default weights, explicitly labeled in `equations.json`. If a saved solver
cost is available, the reconstructed sum must match it (relative tolerance 1e-5)
or inspection rejects the mismatch. Without a saved solver total there is no
independent total check. This is a reconstruction under the current model/code,
not a serialized history of the optimizer's internal iterations.

**Current implementation detail:** the terminal node retains foot-wrench barriers
but evaluates zero terminal wrenches. Each foot therefore contributes 2,000 with
default weights because of the minimum-normal-force bound. This accounts for
4,000 of the shallow reference's total cost of about 4,011.555. The plot exposes
this artifact; it does not mean the robot lands badly or spends 4,000 units of
energy. This observability change preserves the optimizer's behavior.

The saved `optimizer_u` removes export's interval-mean damping compensation from
`tau`; it is the torque used by the optimizer's control cost.

## Equation 2b: what produces the acceleration

The two force-balance panels select the floating-base vertical coordinate (N)
and left knee (N m). They plot signed values of:

```text
M a + C = B u + J^T F_contact + passive + other_constraint
```

- `M a`: mass matrix times generalized acceleration, including model armature.
- `C`: MuJoCo bias force (gravity and velocity-dependent effects).
- `B u`: PD actuator plus explicit feedforward generalized force.
- `J^T F_contact`: all simulated contact forces/moments mapped to generalized forces.
- `passive`: MuJoCo passive forces, including joint damping.
- `other_constraint`: remaining constraint forces, including joint friction loss
  and any active limits. This is not another motor command.
- `LHS - RHS`: the remaining signed force-balance residual.

All 35 coordinates are saved, so other joints can be examined without rerunning.
The first three coordinates have force units N; the other 32 have torque units
N m. Do not combine them into a single dimensional norm.

Measurements use an independent copy of simulation data and the same model and
solver settings, evaluated at each **substep start**. They expose continuous
forward-dynamics acceleration, not a finite difference of velocities after Euler
integration (which treats damping implicitly). Actor observations and the live
simulation are unchanged. CLI state status is at the control-interval end;
the equation-2b timestamp identifies the last substep start in that interval.

**A nonzero residual can reflect finite solver convergence.** The current asset
uses only three solver iterations and five line-search iterations. Some snapshots
leave noticeable residuals; an independent check with higher iteration limits
reduces them to numerical roundoff. We retain the configured simulation settings
and report the residual honestly. This residual is distinct from
`reference.validate`'s inverse-dynamics check of the optimized reference.

For MuJoCo's force conventions, see its
[computation documentation](https://mujoco.readthedocs.io/en/stable/computation/index.html).

## Equation 2c: what it means to keep a foot planted

For each configured sole origin, diagnostics compute a world-aligned 6D Jacobian:

```text
sole velocity     = J v
sole acceleration = J a + Jdot v
```

The linear and angular speed panels show norms separately, in m/s and rad/s.
The left/right vertical-acceleration panels show the signed `J a`, `Jdot v`, and
their sum in m/s². All six components of each term are saved. The displacement
panel measures distance from the initial sole world position, not motion relative
to the pelvis. Ideal fixed contacts have zero velocity and acceleration.

These are actual foot-motion diagnostics evaluated even if contact is lost.
Use the existing contact-force/count traces to distinguish contact from flight.
MuJoCo's compliant contacts need not satisfy the optimizer's rigid-contact
constraint exactly. The constraint residual is therefore an observation, not an
extra episode termination criterion.

The impact branches (`M(v+ - v-) = J^T Lambda`, `J v+ = 0`) are explicitly marked
**not modeled**. This squat has fixed planned contacts; the tool does not invent
an impulse value for a contact-force spike or for a fall.

## Inspect individual values

```python
import numpy as np

with np.load("runs/equations_ff_01/equations.npz") as e:
    k, substep = 40, 0
    print("time:", e["time"][k, substep])
    print("base vertical M a [N]:", e["inertia"][k, substep, 2])
    print("left sole J v [m/s then rad/s]:", e["sole_velocity"][k, substep, 0])
    print("cost names:", e["cost_names"])
    print("planned interval costs:", e["running_cost"][k])
    print("terminal costs:", e["terminal_cost"])
```

Generalized vectors have shape `(executed intervals, 10, 35)`; sole vectors have
shape `(executed intervals, 10, 2, 6)` in left/right order and linear-xyz then
angular-xyz order. `time` has shape `(executed intervals, 10)`. Objective arrays
cover all reference intervals; `objective_time` includes the terminal state.
